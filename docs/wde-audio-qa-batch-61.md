## Rationale & scope

- Existing `WDE_Verify_Sermon_Segment_Audio` uses synchronous External Services, which cannot reliably analyze long video within 120s. Prior provider 503/read timeout left two bounded terminal `SYSTEM_ERROR` segments; 2 PASS and 6 genuine FAIL outcomes are unchanged.
- An Apex/Queueable Gemini Batch proof of concept could not validate under the gateway's Salesforce Integration user: ApexClass `Not available for deploy for this organization` (deployment `0Affj00000aMdArCAK`). That prototype and manifest are removed from this PR. The working replacement is **Flow-only** with Gemini background **Interactions API** (not Gemini Batch API) via existing Named Credential `GeminiNmCred`; no credentials in source and no new GitHub external runtime.
- Isolated manual autolaunched Flows: `WDE_Start_Segment_Audio_Async_QA` for one provider POST, `WDE_Get_Segment_Audio_Async_QA` for provider GET, and `WDE_Delete_Segment_Audio_Async_QA` for explicit provider DELETE. None contains scheduled/record triggers. No automatic Audience Needs/HIVE or transcript updates.
- New External Service `WDEGeminiAsync` with start/get/delete operations and four nullable fields on `Sermon_Segment__c`: `Audio_QA_Batch_State__c`, `Audio_QA_Batch_Job__c`, `Audio_QA_Batch_Fingerprint__c`, `Audio_QA_Batch_Error__c`. Names use historical Batch prefix but the provider API used here is background Interactions.
- New permission set `WDE_Audio_QA_Async_Operator` grants read/write **only** to these four new fields; explicitly assigned to the verified active `AI RCA Integration` user, after checking no prior assignment.

## Manual execution runbook (one selected segment at a time)

1. Verify Organization Id `00Dfj00000eVCOVEA4`, Source Rights `PermissionGranted`, `Audio_QA_Required__c=true`, segment closed, `Audio_QA_Status__c=SYSTEM_ERROR`, attempts at least 3, and `Audio_QA_Batch_State__c` / `Audio_QA_Batch_Job__c` both null.
2. Via **same Chat gateway Issue**, invoke Flow `WDE_Start_Segment_Audio_Async_QA` **exactly once** with `{"inputs":[{"varS_SegmentId":"<one ID>"}]}`. Flow checks eligibility and submits `background:true,store:true` to provider with YouTube URL, video offsets and bounded transcript. It returns confirmed `varT_AsyncId` and `varT_AsyncStatus` but does not itself commit job id to Salesforce. If HTTP times out/receipt is ambiguous, **do not replay**. Confirm provider outcome first.
3. If provider confirms accepted job id, persist exactly `Audio_QA_Batch_State__c=SUBMITTED` and `Audio_QA_Batch_Job__c=<accepted id>` in the same segment using one targeted Sf Request PATCH, then SOQL readback. Do not edit `Audio_QA_Status__c`, attempts, original/corrected transcript, checked timestamp, Audience or HIVE during submission. This split submit/claim path is not fully atomic: a second operator could submit before the PATCH; require single-operator discipline and preflight, and improve idempotency before high-volume use.
4. Via gateway, invoke Flow `WDE_Get_Segment_Audio_Async_QA` for the **already persisted** ID. If `in_progress`, leave unchanged and poll later without resubmission. If `completed` with a model text, independently confirm that the full audio evidence refers to the requested time range and current transcript, that video was truly accessible, and that the response has nonfabricated PASS/FAIL with specific audible facts and timestamps; never infer PASS from HTTP 200. The Flow's model-text extraction is only a **format gate**, not comprehensive source-audio verification.
5. Check readback for unchanged video ID, offsets, transcript, rights, segment ID and QA status before any verdict write. A human or independent verification step must assess actual audio before promotion; a provider failure/status error remains `SYSTEM_ERROR`. Do not overwrite genuine historical `FAIL` or automatically replace transcription.
6. After accepted output is retained in the private audit and Salesforce evidence, invoke the single-ID `WDE_Delete_Segment_Audio_Async_QA` Flow. Verify provider DELETE status; do not delete before preserving evidence. Handle non-confirmed deletion as outstanding retention work, not success. This background mode uses `store:true` and may incur storage/processing costs.
7. No mass retry or provider calls for unflagged segments. The 15.9-min segment is a **separate, subsequent** controlled candidate only after the short pilot is checked.
